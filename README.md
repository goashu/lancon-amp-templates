# LANCON AMP templates

Custom Call of Duty 2 (2005) multiplayer dedicated-server template for **Windows x64**, targeting **AMP 2.8.0.8**. Original game files must be installed separately from a licensed Steam installation. This repository contains no game binaries, keys or credentials.

**Status: statically validated; AMP import and game runtime remain untested.** This is a candidate for LAN testing, not a claim of a working runtime. It deliberately supports only native Windows, without Docker, Wine, mods, SteamCMD or external downloads.

## Add the repository to AMP

1. Open the active **ADS01** management panel.
2. Go to **Configuration -> Instance Deployment -> Configuration Repositories** and add:

   ```text
   goashu/lancon-amp-templates:main
   ```

3. Click **Fetch**, wait for completion, then refresh the browser.
4. Create a **new** instance on the Windows target. Search for **Call of Duty 2 (2005) - Windows LAN**, under the **LANCON** repository prefix. Use native Windows, without a container.
5. Leave automatic game startup disabled until the game files have been installed. An automatic deployment update only prepares a directory; it does not install CoD2.

Use the repository setting rather than manually copying files into DeploymentTemplates. Fetch and inspect ADS logs if the entry is missing. Do not restart ADS01 as a troubleshooting prerequisite. The active datastore is the one ADS01 actually uses; a second copy on another drive does not configure the active installation.

## Install the game into the new instance

1. Install CoD2 separately using Steam. Keep the server and all LAN clients on a matching game/patch version; the intended baseline is the original 1.3 release.
2. Open the new instance in AMP. Run **Update** if deployment has not already done so. This only creates `main` beneath its game directory.
3. With this new server stopped, copy the **contents of the complete CoD2 installation** into the new instance's `call-of-duty2` directory. Include the executable, original DLLs, `main` data archives and language data. Do not copy only the EXE or put an extra `Call of Duty 2` folder around it. Leave existing game servers alone.

   ```text
   <new instance datastore>\
     GenericModule.kvp       # managed by AMP
     call-of-duty2\
       CoD2MP_s.exe
       <original game DLLs and other installed files>
       main\
         <original game data archives>
         lancon.cfg          # generated by AMP at startup
   ```

   For an instance created beside the active ADS01 on E:, the usual game path is `E:\AMPDatastore\Instances\<new-instance-name>\call-of-duty2\`. Verify it in the new instance's File Manager rather than assuming every deployment uses this location. Do not install the game into ADS01's DeploymentTemplates folder.

4. Ensure the Windows account running the new AMP instance can read/execute the game and write its config/logs. Steam's EXE may have first-run, Steam-client or user-session requirements: these have not been tested under the AMP service account. Do not bypass licensing or replace the executable with a crack.
5. Configure the server name, maximum players, game mode, map rotation and optional join password in the **Call of Duty 2** settings. The network game port defaults to **UDP 28960**; AMP owns port allocation and supplies the selected value at launch. Check the actual assigned port, especially if another instance already uses 28960. Select the LAN interface if binding to a specific address; `0.0.0.0` listens on all IPv4 interfaces.
6. Click **Start**. AMP writes `main/lancon.cfg` and launches the executable directly with:

   ```text
   +set dedicated 1 +set net_ip <binding> +set net_port <assigned UDP port> +set sv_maxclients <slots> +exec lancon.cfg +map_rotate
   ```

7. Allow the selected UDP port through Windows Firewall for the LAN network/profile if needed. No internet port forwarding is needed. Dedicated LAN mode is not a firewall: restrict access to the intended LAN.
8. From a matching CoD2 client, use the Local/LAN browser or open its console and run `connect <server-LAN-IP>:<assigned-port>`. If a join password is set, enter it in the client before connecting (`password <your-password>`). Test from a second LAN computer.
9. Use **Stop** in AMP and verify that this instance's `CoD2MP_s.exe` exits. The template requests `WM_CLOSE`, with a 30-second timeout; graceful shutdown, timeout/fallback behavior and Windows service-session handling need runtime verification. Do not assume an unsupported STDIN `quit` command works.

## Defaults and configuration

- Server name: `LANCON CoD2`; 32 slots (UI range 1-64).
- LAN dedicated mode: `dedicated 1`, fixed in the launch arguments.
- UDP game/browser port: 28960 by default; no separate Source RCON or Steam query ports.
- Team Deathmatch (`tdm`), then `mp_toujane`, `mp_carentan`, `mp_burgundy`, `mp_dawnville` in rotation. Other choices: `dm`, `sd`, `ctf`, `hq`.
- The default rotation contains only `map` tokens, so changing Game Mode affects the rotation. Optional `gametype` tokens in a custom rotation override that selection. Use maps present in your installation.
- Join password empty; RCON disabled; no published admin password. PunkBuster off; pure server on; downloads off; no reserved player slots; friendly fire off; killcam on; TDM limit 20 minutes/100 points.
- Config and game logging enabled. Look for `main/games_mp.log` and `main/console_mp.log` if produced by your game build; log locations/content need runtime confirmation.

Restart the game server after changing settings. AMP generates `main/lancon.cfg` using explicit mappings, without a hand-installed seed config. Do not edit that generated file for managed settings. Add any advanced settings deliberately to the metaconfig in your own fork and validate them.

Use single-line names/passwords without double quotes, backslashes, newlines or semicolons. The metaconfig uses CoD2's quoted config syntax; this template does not claim escaping or server-side input validation for arbitrary administrator-supplied strings. The map rotation should use only valid `map`/`gametype` tokens. Passwords are stored in plaintext in the instance config by the game; keep instance files/backups private and never commit them here.

## Console, RCON and status limitations

The Windows executable's GUI console is not assumed to be STDIN/STDOUT. Both AMP console flags are off. `STDIO` is a disabled transport here, not a claim of an interactive console. No Quake RCON connection, admin port mapping, player-count query, join/leave parser, chat parser, health query or universal sleep is enabled.

`ApplicationReadyMode=Immediate` means AMP can label a launched process **Ready** before a map loads. It is only process state, not proof of a responding server. AMP player counts are not authoritative in this version. A launch error, blocked Steam prompt or hung process requires inspection and a client connection test. Automatic retries are disabled during this initial validation stage.

RCON protocol compatibility with this exact executable and AMP version remains unverified. If added later, test CoD2's protocol explicitly, use a private generated password, verify startup/readiness and `quit`, and avoid treating generic Quake RCON support as proof of CoD2 compatibility.

## Static validation

No extra package installation is required. Run Windows PowerShell from this checkout:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\validate.ps1
# Optional comparison with a separate checkout of CubeCoders/AMPTemplates:
powershell -NoProfile -ExecutionPolicy Bypass -File .\validate.ps1 -UpstreamPath C:\path\to\AMPTemplates
```

The validator checks the exact publishable file set, JSON parsing, KVP syntax/duplicate keys, embedded JSON, required metadata, UUIDs, filename case/references, config mappings/defaults, executable and working paths, LAN arguments, map tokens, UDP port and installation stages. The optional upstream check verifies KVP key names and ID uniqueness against that checkout. It is a custom static validator, **not an AMP schema validator or a game emulator**.

Research baseline: [official AMPTemplates](https://github.com/CubeCoders/AMPTemplates/tree/aa716232ba4f1718043b8373bb6b6338b4cff3f0), especially `manifest.json`, `call-of-duty4mw.*`, `call-of-dutymw3.*`, `longvinter.kvp` and `quake3-arenametaconfig.json`; [official Generic module documentation](https://github.com/CubeCoders/AMP/wiki/Configuring-the-%27Generic%27-AMP-module); and the [LinuxGSM maintainers' CoD2 configuration](https://github.com/GameServerManagers/Game-Server-Configs/blob/main/cod2/server.cfg) for basic game configuration. Runtime behavior must still be checked against the original game.

## Findings in the earlier experimental template

Comparison used `LANCON_CoD2_AMP_Template_Windows.zip` and the supplied `LANCON_CoD2_AMP_Template_Windows_v2.zip`, both in Downloads. The active E: deployment folder is on another PC and was unavailable in the authoring session, so this is not a claim that its contents are identical to either ZIP.

The ZIPs' JSON, lowercase names, AppConfigId and config references were already structurally reasonable. The first ZIP did **not** include a repository `manifest.json`; its README instructed manual placement in a local folder. The v2 ZIP adds a manifest, but its `origin` is `https://lanconnection.ch/`, a website rather than a clonable Git repository, and its `url` also points to that website. Its application/settings/metaconfig/ports files are unchanged. The new repository supplies its own UUID, GitHub Git origin, repository URL, prefix and `AppTemplates` type and follows the documented Fetch workflow. The exact cause of ADS discovery failure still needs the active folder/logs; the incorrect v2 origin is a repository-fetch configuration defect, not proof of the local discovery failure's cause.

Other changes:

- Replaced `AutoMap` plus a manually renamed example config with explicit config generation and a directory-preparation update stage.
- Mapped maximum players to AMP's `$MaxUsers`, also supplied before config execution, rather than a separate `sv_maxclients` setting that could disagree with AMP.
- Bound `net_ip` as well as the allocated UDP port; the previous command only set the port.
- Removed default `gametype tdm` tokens that would override a changed Game Mode.
- Replaced RCON-dependent readiness and `String`/`quit` shutdown with explicit process readiness and a documented Windows close request. Disabled unverified console flags and RCON rather than claiming they work.
- Disabled game downloads and automatic restart attempts; documented the exact manual installation layout and remaining runtime checks.

## Runtime acceptance checklist (all pending)

- Fetch public repository on active ADS01 2.8.0.8; template appears and a separate Windows instance is created.
- Update prepares `main`; manual licensed game installation is recognized.
- Start creates the expected config and launches the correct executable, working directory and allocated port under the actual service account.
- A second LAN client joins; hostname, join password (including clearing it), player cap, selected mode and map rotation are honored.
- Change each setting and restart; test a full server, invalid/missing map, missing executable/data, unavailable port and a failed startup. A live process is not enough to pass.
- Stop exits only this instance's process; repeated Start/Stop and a full map rotation succeed. Record whether graceful close or timeout termination occurs.
- Verify behavior of logs, any first-run dialogs, firewall and Steam requirements. Console/RCON/status remain unsupported until separately implemented and tested.

No ADS restart, drive migration, existing game-server edits or LANCON website changes are part of this repository.
